## ★ OBJECTIVE (operator, 2026-06-12): PREDICTION precision — NOT betting

> "I need precision in prediction, not in betting."

**Definition.** Precision = of the calls the model COMMITS to (a conviction UP/DOWN), what
fraction are right — measured by **sign-truth** (`raw_direction` vs realized move sign), the
metric the §5z `hit`-poisoning fixes just made honest. Low recall is acceptable: the model
may stay silent most windows; when it speaks, it should be right.

**This is a MODEL-side property.** It has nothing to do with the betting/market layer
(`p_up`, fair value, share pricing, penny-sniper, arbitrage). That layer *monetizes*
predictions; it does not make them sharper. So it is explicitly **demoted** below the
prediction work.

**Two ways precision rises — both are model-side, both are prioritized:**
1. **Raise the base edge** so committed calls have signal: §1 class-balanced loss (done),
   §2.5a per-candle ATR barriers (cleaner target), §2 new information.
2. **Sharpen WHICH calls get committed** — the precision *instrument*: §4 calibration +
   meta-gate. A calibrated "65%" that truly wins 65%, gated so only the high-precision
   subset is surfaced, is exactly "commit only when right, else stay silent."

**Prerequisite — already shipped this pass:** the `hit` column was dual-semantic and
poisoned every precision metric (calibration labels, poor-regime blocker, regime-quality).
Fixed to sign-truth (V3_CHANGES_AND_AUDIT §5z + the get_regime_horizon_quality /
analytics.validate_regime_thresholds fixes). **You cannot optimize precision you can't
measure** — this had to come first, and it did.

**The THREE precisions (operator, 2026-06-13) — in strict dependency order:**
1. **SIGNAL precision (direction):** the committed UP/DOWN is right (sign-truth). This is the
   FOUNDATION. A perfect magnitude or path on a *wrong direction* is worthless, so nothing
   below ships until this clears ~56-60% at 5m on committed leans. Levers: §1 (done), §2.5a
   ATR labels, §2 new info, §4 calibration/meta selector.
2. **PRICE precision (magnitude — "how far"):** the §2.5b-ii conditional-quantile regressor
   (pinball q10/q50/q90, vol-aware) replacing the flat ~$40 mean. Acceptance: band width must
   correlate with realized |move| out-of-sample. Built ONTO a proven direction, not before.
3. **PATH precision (the journey — "how it goes up/down from here"):** a path classifier
   (DOWN_DIRECT / UP_THEN_DOWN / DOWN_THEN_UP / CHOP) trained on intra-window shape labels.
   The richest and built LAST — it needs both #1 and #2 trustworthy to mean anything.

**Why this order is non-negotiable:** #2 and #3 are *refinements of a correct call*. They
multiply the value of a right direction and the cost of a wrong one. Sequencing them before
#1 is proven would polish noise. All three are **next-retrain changes** → bundle #2 (+ maybe
#3) into the retrain AFTER v6's direction precision is measured; building them now restarts
v6's measurement clock and stacks unmeasured changes (violates the §5/§7 discipline).

**Reprioritized order under this objective:**
- **DO NOW (precision):** §1 (shipped) → measure sign-truth → §2.5a ATR barriers → §2
  new-information bundle → let §4 calibration/meta mature. Each measured by precision on
  committed leans, NOT betting EV.
- **DEFERRED (betting):** §3 (`p_up` distributional pricing / fair value) — it stays on
  the shelf until prediction precision is PROVEN (5m committed-lean sign-truth ≥ ~56-60%).
  Building a pricing layer on coin-flip predictions prices noise. Fair value is not retired
  (it's the eventual monetization), just gated behind precision.

## 0. The diagnosis V5 is built on

The model is a **DOWN-machine**: it inherited a one-sided lean from net-bearish training
windows. Two facts from the code prove the root cause:

1. **Training has NO class balancing.** In `model.py` the per-sample weight `sw`
   (`model.py:616`) is **recency only** (`recency_w`). If a 30-day window has more DOWN
   candles than UP, DOWN dominates the loss and the model learns to lean DOWN. There is no
   per-class reweighting anywhere in the fit path.
2. **The only de-bias is a band-aid at inference.** `model.py:1649-1661` divides the raw
   probabilities by the class prior raised to `alpha=0.5`. That's a mild, lossy correction
   applied *after* a biased model already collapsed its UP signal. It cannot recover
   information the training loss threw away.

So v4's trend features help the model *see* persistence, but it's still trained on an
imbalanced loss. **V5's headline fix is to balance the loss itself.**

## 1. HEADLINE: class-balanced training (root-cause fix)

> **STATUS: SHIPPED & TRAINED 2026-06-12** (run record: V3_CHANGES_AND_AUDIT.md §5an).
> Class weights confirmed firing per horizon in the training log; the inference-time
> prior-division was retired for classbal bundles; held-out conformal bands shipped in
> the same run. Awaiting the 24h sign-truth scorecard — decision gates in
> MODEL_ROSTER_PLAN.md §5.

**Change:** multiply the existing recency weight by an inverse-class-frequency weight, per
horizon, before every `.fit(... sample_weight=sw)`.

```python
# in train(), per horizon h, after y_train is known:
counts = np.bincount(y_classes[:split_idx], minlength=3).astype(float)  # [DOWN, NEUT, UP]
inv = counts.sum() / (3.0 * np.maximum(counts, 1.0))
class_w = inv / inv.mean()           # normalized so mean weight ≈ 1 (keeps LR scale sane)
# then inside the regime loop, where sw = recency_w[reg_idx]:
sw = recency_w[reg_idx] * class_w[y_train_h]
```

**Why this and not more prior-division:** balancing the *loss* makes the model treat a
missed UP as exactly as costly as a missed DOWN during fitting. The model commits to UP
moves it currently fades. The inference-time prior division (`alpha`) can then be **reduced
or removed** — it was compensating for a bias that no longer exists.

**Guardrails (important — this is the one change that can backfire):**
- Cap the class weight (e.g. `np.clip(class_w, 0.5, 2.0)`) so a rare class in a thin window
  can't dominate.
- Apply to the **directional** classifiers only. The magnitude regressor (`reg_mag`) keeps
  recency-only weighting — magnitude isn't class-imbalanced.
- Bump `MODEL_ARCH_VERSION` → `...-v5-classbal-130-tcn` so it auto-retrains.

**Acceptance test (the only thing that matters):** after a ~24h frozen run,
`python backend/sign_truth_scorecard.py` must show the **UP-lean accuracy and DOWN-lean
accuracy within ~8 points of each other** AND the 5m model-lean row **≥ 55%**. If UP/DOWN
balance but accuracy stays ~50%, the bias was a symptom, not the cause → go to §2.

individually across four retrains — bundle them, judge the bundle against §1's baseline.

## 2.5 Label & evaluation quality (from the 2026-06-12 deep audit)

The full label/alignment audit came back largely CLEAN — triple-barrier entry/scan indices,
P4.3 regime-label offsets, and the regime training-loop indexing are all correct. Three
quality items remain, each verified in code:

### 2.5a Per-candle ATR-scaled barriers (label noise at vol extremes)
`build_sequences` uses ONE scalar threshold (e.g. 0.0008) for the whole 30-day window. In
high-vol candles that barrier is touched by the first wiggle (label ≈ noise); in dead
candles it's never touched (everything labels NEUTRAL). V5: scale the barrier per candle
by local ATR (`threshold_i = k * atr[i]/close[i]`), so a "real move" means the same thing
in every regime. This directly improves what the model learns.

### 2.5b Honest conformal bands (in-sample residuals)
`model.py:829-836` computes the move-size conformal quantiles from the regressor's
residuals **on its own training rows** — in-sample residuals make the band systematically
too narrow, which overstates the new "projected close clears the line" confidence. V5:
compute residuals on the held-out 20% slice instead.

### 2.5b-ii Conditional quantile magnitude (operator-observed: "always ~$40")
Verified root cause: the magnitude regressor uses **squared-error loss** on |move| with
shallow capacity (60 iters × 15 leaves), so it predicts ≈ the conditional MEAN — which for
a mostly-unpredictable quantity collapses to "the average 5m move" (~$40 at current vol)
for nearly every window. The band adds FIXED per-regime residual quantiles (q25–q75 =
only 50% coverage), so the whole display looks frozen while real windows range $5–$150.
UI re-labeled honestly (2026-06-12: "typical move · 50% band · tails run larger").
V5 fix: replace mean+fixed-offsets with **conditional quantile regressors** (pinball loss
at q10/q50/q90, vol/regime-aware) so the band breathes with conditions — and feed the
same distribution into the §3 `p_up` computation. Acceptance: band width must correlate
with realized |move| out-of-sample (today it's constant ⇒ correlation ≈ 0).

### 2.5c Partial-candle train/serve skew — MEASURE FIRST
Serve-time predictions run off the FORMING 1m candle (`handle_kline` updates the last bar
in place); training decision-rows are always complete candles. The final bar's
volume/range/CVD features are systematically smaller early in the minute. The scorecard
now buckets sign-accuracy by second-of-minute (§6 of `sign_truth_scorecard.py`): if the
0-14s bucket is clearly worse than 45-59s, the skew is real → V5 fix is bar-progress
normalization (scale the forming bar's accumulation features by 60/elapsed-seconds).
**Do not fix blind — measure, then decide.**

### (Fixed already, 2026-06-12) In-sample backtest contamination
The "latest 12000 candles" backtest right after a fresh train overlapped ~28% TRAINING
rows — every reported backtest accuracy was silently optimistic. Fixed in `server.py`: the
training split boundary is persisted (`saved_models/train_boundary.json`) and the backtest
now scores only post-boundary candles (+ max-horizon embargo), warning loudly when it
can't. The purged walk-forward was already honest (embargoed folds).

## 3. Magnitude → distributional Polymarket forecast  ⛔ DEFERRED (BETTING layer)

> **Per the OBJECTIVE banner: this is the BETTING layer, not prediction precision. DEFERRED
> until 5m committed-lean sign-truth ≥ ~56-60%.** Pricing a coin-flip prediction just prices
> noise. Kept (it's the eventual monetization), gated behind proven prediction precision.
> The §2.5b-ii conditional quantile magnitude IS still a precision item (it sharpens the
> model's move estimate) — only the `p_up`→share-price/fair-value conversion below is deferred.


The model **already** predicts move magnitude (`reg_mag` + conformal low/median/high band),
now surfaced on the Polymarket card ("Model expects a drop of ≈ $X, band $lo–$hi → projects
close $Y"). V5 turns that point-estimate into the number Polymarket actually prices on:

**`P(close ≥ price_to_beat)`** — a probability, not a sign. With the conformal residual band
already stored (`conformal_residuals[reg][h]`), compute the share of the predicted move
distribution that lands beyond the line:

```
edge = (projected_close - price_to_beat)
p_up = Φ(edge / conformal_sigma)     # or empirical CDF from the residual quantiles
```

That `p_up` maps **directly** to fair share price — bet when `p_up` > market share price.
This is the single highest-leverage Polymarket-specific upgrade: it converts the model from
"which side" to "what's it worth," which is where the actual profit/loss lives.

## 6. Correction: what "auto-learning" actually does

Auto-learning (`model.py:2399-2420`) **only tunes one scalar**: `smoothing_alpha` (the
prediction-smoothing factor), nudging it up when accuracy is low and down when it's good.
It does **NOT**:
- learn or add new features,
- discover new indicators,
- change the price inputs,
- retrain the models.

New features/indicators are a **code change + retrain**, full stop. Auto-learning is a
thermostat, not a researcher. Keep it on (it's harmless and mildly helpful), but it is not
the path to higher accuracy — §1 and §2 are.

## 7. The V5 execution order (PRECISION-first, per the objective)

1. **§1 class-balanced loss — SHIPPED & TRAINED.** Now in the frozen measurement window.
2. **Measure** with `sign_truth_scorecard.py`: did UP/DOWN balance, and did 5m committed-lean

   fair value) — the betting/monetization layer. Not before; pricing noise is worse than
   pricing nothing.

The system is now honest (clean grading), instrumented (grades/precision persisted), and
de-biased at the seams. **The objective is prediction precision; the betting layer waits for
it.** V5 makes the model *correct at the root* first, profitable second.
