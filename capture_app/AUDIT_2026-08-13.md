# Standalone Capture App Audit - 2026-08-13

## Verdict

The standalone recorder now has a coherent forward-data contract for Binance spot, Binance USD-M
perpetuals and Polymarket 5m/15m BTC markets. It is suitable to begin long-running evidence
collection. It does not prove a profitable strategy and it must not be described as capturing
private fills or sources outside the documented stream list.

## Confirmed Defects Corrected

1. Binance L2 deltas had no REST baseline, so books were not reconstructable after startup.
2. Futures sequencing used deltas without a per-session snapshot/recovery boundary.
3. True sequence gaps were flagged but recording continued from an invalid book.
4. Polymarket ignored `price_change`, trade, best-quote, tick and lifecycle events.
5. Polymarket's required text `PING` keepalive was missing.
6. Polymarket discovery restarted every 120 seconds even when tokens were unchanged.
7. Global event ordering selected tomorrow's scheduled rounds instead of current rounds.
8. Polymarket RTDS batched Binance payloads were discarded as an unknown scalar shape.
9. Polymarket market metadata, exact anchors and raw payloads were not durable.
10. Settlement polling searched only 300 global events and could produce no quote/outcome join.
11. Settlement index entries were written before parquet durability.
12. A corrupt/stale settlement JSON index could hide missing outcome rows.
13. ISO close timestamps could terminate a settlement poll.
14. Recorder task failures were swallowed by `gather(return_exceptions=True)`.
15. Quiet buffers did not flush without a new row.
16. Rows crossing an hour boundary were put in the wrong partition.
17. Failed parquet writes detached and lost buffered rows.
18. Windows `fsync` used a read-only descriptor and failed every flush on Python 3.13.
19. Disk protection counted stream directories rather than real clock-hours.
20. Failed deletions were counted as reclaimed bytes.
21. State updates erased fields written by another heartbeat/counter update.
22. Disabled streams were still treated as status failures.
23. A connected socket with no data could be reported healthy indefinitely.
24. Custom data roots under one parent shared one state directory.
25. Futures mark/trade websocket starvation created a silent data hole on this network.
26. Realized funding history and public crowding/positioning series were absent.
27. Manual archive marking required no explicit confirmation.
28. No verified automatic off-machine archive existed.
29. No executable regression suite existed despite earlier verification claims.
30. Cloud archival accepted a same-size object without content verification.
31. One-minute local flush files were uploaded individually, creating avoidable GCS objects.
32. No durable source/row/schema manifest or current-generation pointer existed in GCS.
33. A late write could race the archive marker and make an incomplete partition deletable.
34. The disk guard could race a late writer after observing an archive marker.
35. Deployment did not provision a private lifecycle-managed bucket or scope VM object access.

## Implemented Dataset

Seventeen parquet datasets are enabled by default:

- spot: snapshot, sequenced depth, aggregate trades;
- perpetual: snapshot, sequenced depth, aggregate trades, mark/index/funding, open interest,
  liquidation, realized funding history, positioning ratios;
- Polymarket: metadata, snapshot/delta book, trades, market events, Binance/Chainlink RTDS,
  official settlement.

All exchange/source times remain distinct from local receive time. Connection sessions, sequence
states and fallback source labels allow downstream code to reject invalid or lower-fidelity spans.

## Verification Evidence

### Automated

Sixteen deterministic checks cover storage recovery, partitioning, archive verification, status
merge, both Binance sequence contracts, snapshot refusal, exact Polymarket round candidates,
Polymarket event/reference normalization, positioning joins and settlement reconstruction.

Archive tests now exercise Parquet compaction row reconciliation, SHA-256/CRC32C metadata,
manifest/current-generation publication, late-write marker invalidation and remote tamper
rejection. Cloud objects are immutable/content-addressed so the VM needs create/read access, not
archive deletion rights. Durable receipts live outside the capped data tree, and the remote
`_catalog/` remains discoverable after local Parquet reclamation.

Python compilation, Pyflakes, JSON parsing, `git diff --check`, and Git Bash syntax validation pass.

### Live

Isolated live captures wrote readable parquet for:

- Binance spot depth snapshot/deltas/trades;
- Binance futures depth snapshot/deltas, OI, funding history and positioning;
- Polymarket current books, deltas, metadata/events and RTDS references;
- both Polymarket RTDS source shapes (`binance`, `chainlink`).

Final smoke reconciliation found zero row/file-count differences between state JSON and parquet.
Spot and futures depth both had zero true sequence gaps. Exact Gamma slug lookup returned the same
current-round slug requested.

On the development network, futures `aggTrade` and `markPrice` websocket sockets connected but
sent no market rows. Official REST fallbacks captured the information with `source=rest`, and
health correctly returned `DEGRADED`. Deployment should be considered full fidelity only when
those streams show websocket rows and status has no degraded state.

No Polymarket trade happened during the short smoke. No newly quoted round reached settlement
during the smoke. Those paths are parser/integrity tested, but row growth and quote-to-settlement
intersection remain mandatory first-day operational checks.

## Required Operator Checks

1. Run `python capture_app/run.py --selftest`.
2. Start `python capture_app/run.py --record` under a service manager.
3. After ten minutes, run `--status`; do not accept `DEGRADED`, `NO_DATA`, `STALE` or
   `DISCONNECTED` for a full-fidelity deployment.
4. After one completed 5m and 15m round, verify `polymarket_settlement` grows and its slugs exist in
   `polymarket_market_meta`.
5. After observable CLOB trades, verify `polymarket_trades` grows.
6. Configure and permission a GCS bucket if all history must survive the local disk cap. GCS upload
   logic is unit-tested with a content-verifying fake; a real bucket upload still needs a deployment
   smoke because no cloud bucket was configured during this audit.
7. Alert on non-zero `--status`; the deployment cron currently records failures but does not send
   an external notification by itself.
8. Run `--archive-once` and `--verify-archive` against the real bucket before allowing the local
   cap to reclaim any partition.

## GCS Data-Lake Decision

Raw capture remains Parquet/ZSTD rather than Cloud SQL or one mutable database. Completed
stream/hour partitions are compacted toward 256 MB, uploaded to a private regional Standard bucket,
then lifecycle-managed to Coldline after 90 days and Archive after 365 days. The newest immutable
`_catalog/` record selects the active manifest; consumers must follow it rather than wildcarding
every historical content-addressed generation.

The current GCP project check on 2026-08-13 returned `btc-capture` with `billingEnabled: false`.
No claim of operational cloud retention is valid until the owner enables billing, creates the
bucket, and passes a real upload/verification smoke.

## Training Rules

- Exclude Binance depth sessions after a `GAP` until the next snapshot/session.
- Deduplicate aggregate trades by `(symbol, agg_id)` and retain `source`.
- Do not mix `source=rest` receive latency with websocket latency studies.
- Join Polymarket by condition/token/slug/anchor, not rounded wall-clock time.
- Use only final settlement rows as labels.
- Treat absent rows as missing, never neutral or zero.
- Build bars/features from immutable copied partitions, not the live writer directory.

## Deployment and Data-Completeness Addendum

Added independent Bybit perpetual top-of-book/trades, Coinbase BTC-USD ticker, full Deribit BTC
option-chain snapshots, and Pyth BTC/USD observations. Cross-venue rows preserve exchange time,
local UTC receive nanoseconds, monotonic receive nanoseconds, session identity and raw payload.
Added `--quality` for durable Parquet growth, freshness, corruption and schema-drift checks, plus
VM event-loop lag, RSS and free-disk telemetry.

An isolated 25-second live smoke wrote 270 Bybit quote rows, 125 Bybit trade rows, 25 Coinbase
ticker rows and 3,272 Deribit option rows with no parser or persistence errors. The upgraded Pyth
endpoint returned HTTP 401 without a key; the legacy endpoint returned HTTP 200. This is not
hidden by a fallback. Deployment supports a root-only `/etc/btc-capture.env` populated from
`PYTH_API_KEY` and `PYTH_ENDPOINT` without committing either value.

Profitability status is unchanged: complete causal data makes a claim testable, not true. No
public recorder can prove private queue priority or actual fills, and capital authority remains
blocked until forward settlement joins and execution-cost lower bounds pass.

The first all-stream smoke revealed synchronous Parquet/status writes could delay the event loop
by tens of seconds under load. Threshold/timed Parquet compression now runs in one guarded worker
per stream, state-file writes are coalesced to at most once per second unless urgent, and shutdown
waits for recorder final flushes before cancellation. `collector_runtime` now preserves loop lag,
CPU, RSS and disk metrics every five seconds; three consecutive pressure samples are required
before the deployment is marked degraded.

The post-fix 75-second all-stream smoke ended with `quality_ok=true`, zero required-stream errors,
official settlement rows present, and valid rows for every enabled source. Only liquidations had
zero rows, which is a legitimate quiet-event warning. The development workstation was already
running multiple independent recorders, so its transient loop-lag result is not used to approve an
`e2-micro`; the deployed VM must pass a dedicated 24-hour capacity/continuity soak.
